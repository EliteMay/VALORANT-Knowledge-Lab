# Research 01 — Lurk / Anchor / Cover & Trade

Research date: 2026-09-19

## Research Question

VALORANTでラーク、アンカー、カバー / トレードを上級者レベルで理解するために、何を見て、何を目的に、どう判断すべきか。

## Research Policy

- VALORANT固有の戦術Claimはプロ本人・Coach・IGL・信頼できるInterviewを優先する。
- FPS一般のCommunication / Coordinationは査読研究で補強する。
- Exact Numberは公式仕様または計測根拠がなければ普遍Ruleにしない。
- 同じOriginal発言の転載は独立Evidenceとして数えない。

## Lurk — Current Synthesis

### Supported

- Lurkの中核は「一人でゆっくり歩くこと」ではなく、**相手の配置・Rotation・空いたSpace・過去Round patternを読み、Timingを取ること**。
- Roundごとに相手の傾向を学び、同じPatternを固定化しない。
- TeamのMain groupと情報を同期しないLurkは価値が落ちる。
- Killだけでなく、Map control、RotationのPunish、Defender pushの検知などがValueになり得る。

### Context-dependent

- 「Sentinel / ControllerがLurkするべき」という固定Role Ruleにはしない。
  - nAts本人はどのAgentでもLurk可能としている。
  - 一方でAgent abilityやMain groupで必要な役割によって実用性は変わる。

### Practice Question

VODで自分のLurk deathを見るとき:

1. Lurk開始時点で何の情報があったか。
2. Main groupは何をしていたか。
3. 相手の過去Round patternを使ったか。
4. 自分が取ったSpaceはTeamのActionに繋がったか。
5. Killがなくても得た情報 / 制限したRotationはあったか。
6. RegroupすべきTimingを逃していないか。

# 2. Anchor

## Evidence Map

### Source A1 — nAts Cypher Interview

- Type: Pro Practice / Strong Secondary
- Tier: B

- Date: 2023-04-25

  - Infoを得た後にCoverやDefensive positionを変える考え方が出ている。

### Source A2 — Current Coaching Cross-check

- Type: Coaching Heuristic / Supplementary
- Tier: C
- Source: BO3.gg, "How to Anchor a Site as a Sentinel: Cypher and Killjoy Setups"
- Date: 2026-08-21
- URL: https://bo3.gg/valorant/articles/how-to-anchor-a-site-as-a-sentinel-cypher-and-killjoy-setups
- Relevant points:
  - Anchorの目的を「5人全員を倒す」ではなく、ExecuteをDelayし、Hit directionを確認し、良いFightを取り、味方Rotateまで生存することとして整理。
- Applicability:
  - nAts InterviewのHold / Delay中心の考え方をCurrent coaching articleが独立に補強。
- Limitation:
  - Pro本人の一次Sourceではないため、A1よりEvidence weightを低くする。

## Anchor — Current Synthesis

### Supported

- Anchorの成功条件をKill数だけに置かない。
- 主なValueは、敵のCommitを見極める、進行を遅らせる、Site controlのCostを上げる、Rotateまで時間を作ること。
- Utilityは「置いたから終わり」ではなく、敵のEntry方法に応じて機能するかを見る。
- 可能なら同時に複数人とFightせず、Info / Utility / Coverを使ってFightを分割する。

### Context-dependent

- 生存を優先するか、Site内でFightするかはRetake viability、味方位置、Ultimate / Utility、Spike、人数等で変わる。
- SentinelだけがAnchorできると断定しない。

### Practice Question

1. 敵5人を止めようとして無理なMulti-fightをしていないか。
2. 「敵がCommitした」という確定情報を何で取ったか。
3. Utilityで何秒ではなく、どのActionを遅らせたか。
4. 味方Rotateまで生存できるPositionだったか。
5. 同じSetupが読まれていなかったか。

# 3. Cover / Trade

このConceptは「カバー」を1種類にまとめず、少なくとも次を分けて扱う。

- Trade cover — 味方のContact後にRefragできる位置関係
- Angle cover — 味方が見られないDanger angleを担当
- Utility cover — Flash / Recon / Smoke等で味方Actionを成立させる

初回Researchでは主にTrade + Team coordinationを扱う。

## Cover / Trade — Current Synthesis

### Supported / Cross-checked

- Tradeは「味方が死んだあと何となく出る」ではなく、Contact前から**Refrag可能なLine of sight / timing / spacing**を作る必要がある。
- 近すぎると同じSpray / Utility / body congestionで一緒にPunishされるRiskがある。
- 遠すぎる、またはLine of sightが切れると、OpponentがReset / repositionする時間を与える。
- CoverはTradeだけではなく、別Angleを担当する、UtilityでActionを通す等に分けて学習した方が判断しやすい。
- Tactical FPS研究では、事実・Action中心のCalloutと共有KnowledgeがCoordinationに関わることが示されている。

### Do NOT promote to universal rule yet

- 「必ず5m」
- 「必ず1秒以内」
- 「常に同じ角度からSwing」
- 「前の味方を必ずbaitしてTrade」

これらはMap geometry、weapon、movement、Utility、角度で変わる。Exact thresholdのCurrent reliable evidenceは未確定。

### Practical Decision Model

```text
味方がContactする
↓
自分は同じThreatへすぐAction可能？
├─ No → 遠すぎる / LOSが切れている / 別角度担当を再確認
└─ Yes
   ↓
同じSpray / Utilityで2人同時にPunishされる？
├─ Yes → 近すぎる / 重なりすぎ
└─ No → Trade-ready
```

これは複数Evidenceを学習用に整理した Site Synthesis であり、公式VALORANT Ruleではない。

# 4. Cross-topic Finding

3Conceptに共通して強く出てくるのは、**Positionそのものより、Information → Decision → Actionの連結**。

- Lurk: 敵配置 / Pattern / Main group info → Timing / Spaceを取る
- Anchor: Commit info → Delay / Fight selection / reposition
- Trade: Contact / teammate state / threat location → immediate coordinated action

このモデルはInitial Site IAで「情報から判断する」ことを中心に置く理由になる。

ただし、このCross-topic modelはSite Synthesisとして明示し、nAtsや論文がそのまま同じFormulaを提示したとは書かない。
